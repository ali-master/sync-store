## Dashboard settings

Settings that can change while the API runs are edited in the dashboard under **Settings** (platform administrator only) and stored in MongoDB, in the `installation_settings` collection. Each one is named after the environment variable it overrides:

1. A value saved in the dashboard wins.
2. Otherwise the environment variable applies.
3. Otherwise the built-in default.

A change reaches every replica within five seconds, without a restart. Saved values are validated together before they are stored: the dashboard refuses, for example, a half-configured SSO provider or an origin list that is not exact origins. **Use environment value** removes a saved value. Secrets (`SSO_CLIENT_SECRET`, `METRICS_TOKEN`) are write-only: the API reports whether they are set, never their value. Every change is recorded in the **Activity log** as `admin.settings.update` with the names of the changed settings.

| Setting                  | Dashboard group | Purpose                                                                                                                                       |
| ------------------------ | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `API_URL`                | General         | Public API URL; its origin is the SDK `serverUrl` shown in **Connect your app**, and the base of the MCP, metrics and SSO callback addresses. |
| `CORS_ALLOWED_ORIGINS`   | General         | Exact browser origins, or `*`. Applies to HTTP, Socket.IO and the MCP endpoint.                                                               |
| `HISTORY_RETENTION_DAYS` | Data            | Retention of newly captured history versions, 1–3650 days.                                                                                    |
| `SSO_*`                  | Single sign-on  | See [dashboard single sign-on](/docs/guides/dashboard-sso).                                                                                   |
| `METRICS_TOKEN`          | Monitoring      | Bearer token for `/metrics`, at least 32 characters.                                                                                          |

Everything the API needs before it can read the database stays environment-only: `DATABASE_URL`, `REDIS_URL`, `SOCKET_IO_PREFIX`, `JWT_SECRET`, `CSRF_SECRET`, `PORT`, `TRUSTED_PROXY_CIDRS` and the TLS overlay settings.

## API environment

| Setting                  | Purpose                                                                                                                |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`           | Required MongoDB URL; `mongodb://` or `mongodb+srv://`.                                                                |
| `API_URL`                | Explicit public API URL, e.g. `http://localhost:3000`.                                                                 |
| `PORT`                   | Listener port, default 3000.                                                                                           |
| `HISTORY_RETENTION_DAYS` | Retention for newly captured history snapshots; default 30, integer 1–3650. Use the same value on all replicas.        |
| `TRUSTED_PROXY_CIDRS`    | Comma-separated IPs/CIDRs of directly connected terminating proxies; empty trusts none. Applies to HTTP and Socket.IO. |
| `TLS_CERT_DIR`           | Compose TLS overlay: directory containing `fullchain.pem` and `privkey.pem`.                                           |
| `TLS_BIND_ADDRESS`       | Compose TLS overlay: host bind address for port 443; defaults to `127.0.0.1`.                                          |
| `NODE_ENV`               | `development`, `test` or `production`; the runtime is still Bun.                                                       |
| `JWT_SECRET`             | Required application secret. This does not add JWT authentication to the sync routes.                                  |
| `CSRF_SECRET`            | Required application secret, at least 32 characters.                                                                   |

The Nest application reads its environment files, including `apps/api/.env.local`. Explicit shell variables are useful for Prisma and database setup commands. Keep deployment secrets outside images and source control.

No initial API-key environment variables are required. Open `/dashboard/` and complete onboarding with the setup code from the API logs to create your administrator credential. See [dashboard and credential recovery](/docs/guides/dashboard).

### Dashboard single sign-on

All optional. Setting `SSO_ISSUER` or `SSO_CLIENT_ID` turns the feature on, and the API then requires the others marked required. See [dashboard single sign-on](/docs/guides/dashboard-sso).

| Setting               | Purpose                                                                 |
| --------------------- | ----------------------------------------------------------------------- |
| `SSO_ISSUER`          | Required. OpenID Connect issuer URL of your identity provider.          |
| `SSO_CLIENT_ID`       | Required. Client ID registered with the provider.                       |
| `SSO_CLIENT_SECRET`   | Client secret; omit for a public client.                                |
| `SSO_REDIRECT_URI`    | Required. `<API origin>/api/v1/sso/callback`, as registered.            |
| `SSO_ALLOWED_EMAILS`  | Comma-separated addresses that may sign in. One allow-list is required. |
| `SSO_ALLOWED_DOMAINS` | Comma-separated email domains that may sign in.                         |
| `SSO_PROVIDER_NAME`   | Sign-in button label; default `SSO`.                                    |
| `SSO_SCOPES`          | Requested scopes; default `openid email profile`.                       |
| `SSO_SESSION_MINUTES` | Console session lifetime, 1–1440; default 480.                          |

### Prometheus metrics

| Setting         | Purpose                                                                                                                                                                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `METRICS_TOKEN` | Optional bearer token for `GET /metrics`. Use a long random value. Without it, only API keys with the `admin` scope can scrape. See [Prometheus metrics](/docs/guides/metrics). |

[Operational reports](/docs/guides/operational-reports) store minute metrics and
metadata-only change events for 90 days. Shared storage-size snapshots run once per
minute across replicas. There is no additional service or secret to configure.
Report retention is separate from `HISTORY_RETENTION_DAYS`; size charts measure
logical values and retained BSON, not physical MongoDB disk usage.

For multiple API replicas, set `REDIS_URL` to the same Redis instance and `SOCKET_IO_PREFIX` to the same installation-specific name (default `sync-store`). Omitting Redis enables single-process mode only. See [scaling](/docs/guides/deployment#scale-websocket-delivery).

Use `DATABASE_URL` to select the MongoDB database. Distributed outbox delivery requires Redis 7.2+ with AOF enabled and permission to run `WAITAOF`. Compose configures this automatically. No additional outbox environment variables are required; the pending-event index is created at API startup. Apply the database migrations before starting the updated API; the Compose `init` service does this automatically.

## Client options used in the supported flow

### Browser origins

`CORS_ALLOWED_ORIGINS` accepts comma-separated exact origins, for example
`https://app.example.com,https://docs.example.com`. Include the documentation origin
when using its playground. Docker Compose forwards this variable to every API replica.
The default `*` intentionally permits public SDK access. Browser cookies and other
ambient credentials are not enabled; clients authenticate explicitly using API-key headers
or Socket.IO authentication. `CORS_ORIGIN` and `CORS_CREDENTIALS` are not supported settings.

The same origin list configures HTTP and Socket.IO CORS responses. CORS is a browser
response policy, not authentication or a WebSocket firewall: API-key permissions and
website restrictions still apply. Use an explicit list for a private installation.

| Option        | Purpose                                                               |
| ------------- | --------------------------------------------------------------------- |
| `serverUrl`   | API origin; defaults to local port 3000.                              |
| `apiKey`      | Application credential.                                               |
| `userId`      | Server-side storage identity; must be authorized by your application. |
| `instanceId`  | Identifies this client instance; use a different value per instance.  |
| `namespace`   | Separates browser cache/outbox storage; not an ACL.                   |
| `mode`        | `websocket`, `http` or `auto`.                                        |
| `autoConnect` | Disable for an explicit connect flow.                                 |
| `timeout`     | Transport timeout in milliseconds.                                    |

Changing cache identity can strand pending writes in the old namespace. Do not silently rotate it on every render.

## Docs and branding

Set `SITE_URL` to the documentation origin **before building**. On Vercel, `VERCEL_PROJECT_PRODUCTION_URL` is used if SITE_URL is absent. Local fallback is `http://localhost:4000`.

Brand files come from the root `assets/` directory. The docs configuration copies logo/social preview assets and generates the SVG favicon on dev/build. Do not edit generated copies.

GitHub repository social preview is a separate Settings upload; site metadata cannot change it.

## Playground

Set `VITE_DOCS_URL` to your documentation URL ending in `/docs` if you host the playground. Enter server URL and the disposable API key at runtime. Never put a private key in a frontend environment variable.
